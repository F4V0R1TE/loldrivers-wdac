# LOLDrivers WDAC Blocklist

A WDAC deny policy for known vulnerable and malicious Windows drivers, generated
automatically from the [LOLDrivers](https://www.loldrivers.io/) data set and
published every week.

**[Download the latest release](../../releases/latest)**

## What this is

A WDAC base policy in multiple-policy format that **allows everything** and
denies the known vulnerable drivers from LOLDrivers by Authenticode hash. It can
run alongside an existing WDAC policy and only contributes the deny rules.

Only kernel mode code integrity (KMCI) is enforced. User mode code is not
evaluated.

Two variants are published:

| Variant | Behaviour |
|---|---|
| `LOLDrivers-Audit.zip` | Logs blocked drivers, blocks nothing |
| `LOLDrivers-Enforced.zip` | Blocks the drivers |

Each archive contains the policy XML and the compiled `.cip` binary. The `.cip`
is named after the policy GUID, which is what Windows expects.

## Deployment

Start with the audit variant. Run it for at least one patch cycle and review the
event log before you enforce anything.

### Manual

```powershell
Copy-Item .\{2fcdc60b-02ca-4907-a413-a927fef4a149}.cip C:\Windows\System32\CodeIntegrity\CiPolicies\Active\
citool --refresh
```

`citool` is available on Windows 11 22H2 and Windows Server 2022 and later.
On older builds, reboot instead.

### Verifying

Blocked drivers appear in **Event Viewer -> Applications and Services Logs ->
Microsoft -> Windows -> CodeIntegrity -> Operational**:

| Event ID | Meaning |
|---|---|
| 3076 | Would have been blocked (audit mode) |
| 3077 | Blocked (enforced mode) |

### Removing

```powershell
citool --remove-policy {2fcdc60b-02ca-4907-a413-a927fef4a149}
```

The policy GUID `{2fcdc60b-02ca-4907-a413-a927fef4a149}` is stable across all
releases, so an update replaces the previous version rather than adding a second
policy.

## Updates

The policy version follows `1.YYYY.M.D`. Because the version increases with
every release, Windows treats a new `.cip` with the same GUID as an update.
`Enabled:Update Policy No Reboot` is set, so updates apply without a restart.

A new release is only published when the set of driver hashes actually changed.
If upstream added nothing, no release appears.

## Repository layout

```
generate.py                      builds the policy XML from the LOLDrivers data
.github/workflows/build.yml      weekly build, compile, commit and release
policies/ruleset.sha256          fingerprint used for change detection
policies/<yyyy-mm-dd>/           one folder per published version
```

The workflow runs every Monday at 03:00 UTC and can be triggered manually.
Policies are compiled and schema-validated with `ConvertFrom-CIPolicy` on a
Windows runner before they are published.

## Limitations

- Hash-based rules match exactly those file versions. Recompiled or patched
  variants of the same driver are not covered.
- The upstream data set contains no page hashes.
- A few samples carry no usable Authenticode hash and are therefore not covered.
  They are listed in `skipped.md` in every release.
- This overlaps with the vulnerable driver blocklist Microsoft ships with
  Defender. It is meant as an addition, not a replacement.

## Warning

A faulty driver policy can leave a machine unable to boot. Test in a
representative environment, deploy in audit mode first, and make sure you know
how to recover a system that will not start. No warranty, no support.
